# Data Model: E-KINERJA GURU

## Overview
Based on the feature specification, the system uses a relational model managed by Prisma V7. It handles multitenancy by `Semester` and access control by `User.role`.

## Core Entities

### User
Extends Better Auth schema.
- `id`: String (UUID)
- `name`: String
- `email`: String (Unique)
- `username`: String (Unique)
- `role`: Enum (ADMIN, PRINCIPAL, TEACHER)
- `isActive`: Boolean (Default: true)
- `createdAt`: DateTime
- `updatedAt`: DateTime

### Semester
Defines the time boundaries for all submissions and evaluations.
- `id`: String (ID generic)
- `name`: String (e.g., "Semester Ganjil 2025/2026")
- `startDate`: DateTime
- `endDate`: DateTime
- `isActive`: Boolean (Only one can be true)
- `submissions`: DocumentSubmission[]
- `evaluations`: Evaluation[]

### DocumentDeadline
Configurable deadlines per document type per semester.
- `id`: String
- `semesterId`: Relation(Semester)
- `documentType`: Enum (RPP, SYLLABUS, LEARNING_ACHIEVEMENT, TIME_ALLOCATION, KKTP, SEMESTER_PROGRAM, ANNUAL_PROGRAM, TEACHING_JOURNAL)
- `deadline`: DateTime

### DocumentSubmission
- `id`: String
- `teacherId`: Relation(User)
- `semesterId`: Relation(Semester)
- `documentType`: Enum (as above)
- `fileUrl`: String (Uploadthing URL)
- `fileKey`: String (Uploadthing Key)
- `uploadedAt`: DateTime
- `status`: Enum (COMPLETED, LATE, MISSING)

### Evaluation
- `id`: String
- `teacherId`: Relation(User)
- `semesterId`: Relation(Semester)
- `evaluatorId`: Relation(User)
- `scores`: Json (Rating 1-5 for each of the 8 items)
- `finalScore`: Float
- `category`: Enum (A, B, C, D)
- `createdAt`: DateTime
- `updatedAt`: DateTime

### EvaluationHistory
- `id`: String
- `evaluationId`: Relation(Evaluation)
- `changedById`: Relation(User)
- `previousScores`: Json
- `newScores`: Json
- `reason`: String (Optional)
- `changedAt`: DateTime

## Better Auth Schema (Internal)
Generated by `bun x auth generate`:
- `Session`
- `Account`
- `Verification`

## Relationships
- **Semester (1:N) DocumentSubmission**: A semester tracks many uploads.
- **User (1:N) DocumentSubmission**: A teacher has many uploads.
- **Semester (1:N) DocumentDeadline**: Deadlines are specific to a semester.
- **User (1:N) Evaluation**: A teacher receives evaluations; a Principal/Admin gives evaluations.

## State Transitions
- **Submission Status**:
  - `MISSING` -> (Deadline passed) -> `MISSING` (Val: 0)
  - `MISSING` -> (Upload before deadline) -> `COMPLETED`
  - `MISSING` -> (Upload after deadline) -> `LATE` (Val: 0)
